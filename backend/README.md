# Новый Go-бэкенд

Go 1.26+, PostgreSQL 17. Команды выполняются из `backend/`.

## Запуск

```sh
export POSTGRES_PASSWORD='local-development-password'
docker compose up -d --wait
export DATABASE_URL="postgres://edm:${POSTGRES_PASSWORD}@127.0.0.1:5432/edm?sslmode=disable"
go run ./cmd/api
```

Имена переменных и значения по умолчанию — в `.env.example`; файл автоматически
не загружается. `sslmode=disable` допустим только для локальной БД.
Сервис применяет встроенные миграции goose перед запуском HTTP. Внешний доступ
к API должен идти через HTTPS. `GET /healthz` — проверка процесса,
`GET /readyz` — проверка подключения к БД.

## Учётные записи

Создание пользователя — через `go run ./cmd/edmctl create-user USERNAME`:
пароль (12–1024 байта) читается из stdin. Публичной регистрации нет. Вход:
`POST /api/v1/auth/login`, JSON с `username` и `password`. Возвращённый токен
передаётся в `Authorization: Bearer …`. Сессия действует 24 часа;
`GET /api/v1/me` возвращает пользователя, `POST /api/v1/auth/logout` отзывает сессию.

## Документы и задания

Контракт: [`api/openapi.json`](api/openapi.json), версия 0.3.0.

| Запрос | Результат |
| --- | --- |
| `GET /api/v1/assignments?limit=50&after=<uuid>` | Свои действующие задания, до 100 за страницу |
| `GET /api/v1/assignments/{id}` | Свое действующее задание |
| `GET /api/v1/documents/{id}` | Карточка документа с действующим заданием |
| `GET /api/v1/documents/{id}/versions/{versionID}` | Метаданные точно назначенной версии |

`items` всегда массив. `next_after` присутствует, если есть следующая страница;
его передают как `after`. Сортировка — UUID по возрастанию. Это постраничное
чтение текущего состояния, а не курсор синхронизации: для новых заданий нужно
начать список заново. Параметры пагинации должны быть одиночными.

Модель первого серверного шага:

- `Document` — стабильный ID и название; `DocumentVersion` — неизменяемые
  метаданные финализированного PDF: номер, размер, SHA-256, время создания.
- БД запрещает обновление и удаление версий; номер уникален внутри документа.
- `Assignment` связан одновременно с документом, точной версией и пользователем;
  составной внешний ключ запрещает назначение версии другого документа.
- Статусы: `pending` и `cancelled`; только `pending` даёт доступ. Ревизия
  предусмотрена для дальнейших проверок актуальности; команд изменения пока нет.
- Задание на одну версию не открывает другие версии того же документа.
  После отмены последнего задания карточка также становится недоступной.
- Чужие, отменённые, отсутствующие объекты и неверные UUID возвращают одинаковый
  `404 not_found`; отсутствующая/недействительная сессия — `401`.
  Ошибка БД — `500`, а не пустой список или отсутствие доступа.

Загрузка, проверка содержимого, файловое хранилище, скачивание и служебное
создание документов/заданий — следующий шаг. Текущие маршруты возвращают только
метаданные; путь хранения в API не передаётся. Реальные документы не добавляются
в репозиторий. Тестовые данные создаются интеграционными тестами в транзакции.

## Проверки

```sh
go test ./...
go vet ./...
go build ./...
```

Интеграционные тесты запускаются с `TEST_DATABASE_URL`, указывающим на отдельную
тестовую БД PostgreSQL. Миграции сохраняются в ней; документные фикстуры
откатываются транзакцией. Без переменной интеграционные тесты пропускаются.

```sh
TEST_DATABASE_URL='postgres://edm:password@127.0.0.1:5432/edm_test?sslmode=disable' go test -race ./...
```

Проверяются сессии, изоляция пользователей, привязка к точной версии и документу,
пагинация, отмена заданий, неизменяемость версий и ошибки БД.
