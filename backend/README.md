# Новый Go-бэкенд

Go 1.26+, PostgreSQL 17. Команды выполняются из `backend/`.

## Запуск

```sh
export POSTGRES_PASSWORD='local-development-password'
docker compose up -d --wait
export DATABASE_URL="postgres://edm:${POSTGRES_PASSWORD}@127.0.0.1:5432/edm?sslmode=disable"
go run ./cmd/api
```

Имена переменных и значения по умолчанию — в `.env.example`; файл автоматически
не загружается. `sslmode=disable` допустим только для локальной БД.
Сервис применяет встроенные миграции goose перед запуском HTTP. Внешний доступ
к API должен идти через HTTPS. `GET /healthz` — проверка процесса,
`GET /readyz` — проверка подключения к БД.

## Учётные записи

Создание пользователя — через `go run ./cmd/edmctl create-user USERNAME`:
пароль (12–1024 байта) читается из stdin. Публичной регистрации нет. Вход:
`POST /api/v1/auth/login`, JSON с `username` и `password`. Возвращённый токен
передаётся в `Authorization: Bearer …`. Сессия действует 24 часа;
`GET /api/v1/me` возвращает пользователя, `POST /api/v1/auth/logout` отзывает сессию.

## Документы и задания

Контракт: [`api/openapi.json`](api/openapi.json), версия 0.4.0.

| Запрос | Результат |
| --- | --- |
| `GET /api/v1/assignments?limit=50&after=<uuid>` | Свои действующие задания, до 100 за страницу |
| `GET /api/v1/assignments/{id}` | Свое действующее задание |
| `GET /api/v1/documents/{id}` | Карточка документа с действующим заданием |
| `GET /api/v1/documents/{id}/versions/{versionID}` | Метаданные точно назначенной версии |
| `GET /api/v1/documents/{id}/versions/{versionID}/content` | Поток PDF; `Range`/`If-Range` для продолжения скачивания |

`items` всегда массив. `next_after` присутствует, если есть следующая страница;
его передают как `after`. Сортировка — UUID по возрастанию. Это постраничное
чтение текущего состояния, а не курсор синхронизации: для новых заданий нужно
начать список заново. Параметры пагинации должны быть одиночными.

Модель первого серверного шага:

- `Document` — стабильный ID и название; `DocumentVersion` — неизменяемые
  метаданные финализированного PDF: номер, размер, SHA-256, время создания.
- БД запрещает обновление и удаление версий; номер уникален внутри документа.
- `Assignment` связан одновременно с документом, точной версией и пользователем;
  составной внешний ключ запрещает назначение версии другого документа.
- Статусы: `pending` и `cancelled`; только `pending` даёт доступ. Ревизия
  предусмотрена для дальнейших проверок актуальности; команд изменения пока нет.
- Задание на одну версию не открывает другие версии того же документа.
  После отмены последнего задания карточка также становится недоступной.
- Чужие, отменённые, отсутствующие объекты и неверные UUID возвращают одинаковый
  `404 not_found`; отсутствующая/недействительная сессия — `401`.
  Ошибка БД — `500`, а не пустой список или отсутствие доступа.

### Служебная загрузка и назначения

Команды доступны оператору с доступом к БД; мобильному пользователю такие права
не выдаются. HTTP-загрузки и публичного административного API пока нет.

```sh
# UUID операции создать один раз и сохранить для повторов.
go run ./cmd/edmctl import-pdf \
  -operation '<operation-uuid>' -title 'Договор' \
  -assignee '<user-uuid>' /private/path/document.pdf

# Новая версия существующего документа; прежние версии и назначения сохраняются.
go run ./cmd/edmctl import-pdf \
  -operation '<new-operation-uuid>' -document '<document-uuid>' \
  -title 'Договор' -assignee '<user-uuid>' /private/path/revised.pdf

# Назначить уже загруженную версию другому исполнителю.
go run ./cmd/edmctl assign-version '<operation-uuid>' '<version-uuid>' '<user-uuid>'
```

`import-pdf` возвращает JSON с `version` и `assignment`. Без `-document` создаётся
новый документ; с ним добавляется следующая версия, название карточки не меняется.
Пользователь должен существовать и быть активным. Вход — обычный локальный файл,
максимум 100 МиБ, таймаут всей команды — 2 минуты. Проверяются заголовок PDF 1.0–1.7/2.0
и конечный `%%EOF`, вычисляются точный размер и SHA-256. **Это базовая проверка формата,
не полный разбор PDF, не антивирус и не проверка электронной подписи.**

Хранилище пилота — PostgreSQL: `file_uploads` и блоки `file_chunks` до 1 МиБ.
Временные блоки, проверка, финализация версии и назначение входят в одну транзакцию.
Непроверенный файл недоступен API; ошибка чтения/проверки/БД, отмена или остановка
CLI приводят к rollback. Незавершённые данные не коммитятся, поэтому отдельная
периодическая очистка временных файлов не нужна. БД должна иметь место для PDF,
WAL и резервных копий; это сознательное решение для ограниченного пилота.
Триггеры запрещают изменение, удаление и дополнение финализированного содержимого.

Повтор выполняется **с тем же ID операции, теми же параметрами и исходным файлом**:
возвращается прежняя версия/задание, дубликаты не создаются. Изменённые параметры
или содержимое дают конфликт. Конкурентные повторы сериализуются в PostgreSQL;
номер новой версии выделяется под блокировкой документа. Если ответ CLI потерян,
повтор безопасен и после перезапуска. Повтор не восстанавливает отменённое задание.
Для другого действия нужен новый UUID; второе действующее назначение одной версии
тому же пользователю отклоняется как конфликт.

### Скачивание

`/content` проверяет сессию и доступ к точной версии на каждом запросе, в том числе
при `Range` и условных запросах. Ответ — `application/pdf`, `attachment` с безопасным
UUID-именем, `Cache-Control: no-store`, `nosniff`, сильный `ETag` с SHA-256.
Содержимое читается порциями, без загрузки всего PDF в память. Поддерживаются
`206`, `If-Range`, `If-Match`, `If-None-Match`; ошибки диапазонов/условий (`416`/`412`)
используют общий JSON-формат. Несовпадение `If-Range` возвращает полный файл (`200`).
Контекст скачивания ограничен 25 секундами, HTTP write timeout — 30 секундами.
После обрыва клиент продолжает через `Range`/`If-Range` и сверяет итоговый размер
и SHA-256 с метаданными перед просмотром. Отзыв доступа действует со следующего
запроса; уже начатую передачу не отзывает. Отсутствие содержимого при доступных
метаданных — `500`, а не `404`; ошибка после начала передачи обрывает тело ответа.

Реальные документы не добавляются в репозиторий. Скачивание не означает
ознакомления, согласования или подписания.

## Проверки

```sh
go test ./...
go vet ./...
go build ./...
```

Интеграционные тесты запускаются с `TEST_DATABASE_URL`, указывающим на отдельную
тестовую БД PostgreSQL. Миграции сохраняются в ней; метаданные старых документных
тестов откатываются транзакцией. Сквозные тесты импорта сохраняют синтетические
PDF и учётные записи, поскольку проверяют реальные коммиты и неизменяемость;
рекомендуется одноразовая тестовая БД. Без переменной интеграционные тесты пропускаются.

```sh
TEST_DATABASE_URL='postgres://edm:password@127.0.0.1:5432/edm_test?sslmode=disable' go test -race ./...
```

Проверяются сессии, изоляция пользователей, привязка к точной версии и документу,
пагинация, отмена заданий, неизменяемость версий и ошибки БД. Для файлов проверяются
конкурентные повторы, конфликты ID/содержимого, новые версии, назначения,
ошибочные/прерванные/слишком большие загрузки и rollback, точное скачивание,
продолжение на границе блоков и запрет доступа после отмены задания.
